```mermaid
        Entry->>Orch: generate_workplan_artifacts
    end

    Orch->>Agent: WBSGeneratorAgent.run(parsed_brief)
    Agent->>LLM: call_structured → WBS
    LLM-->>Agent: WBS
    Agent-->>Orch: WBS
    Orch->>Session: session.wbs = ...

    Orch->>Agent: RAIDGeneratorAgent.run(parsed_brief, wbs)
    Note over Orch,LLM: warm_raid_build_prefix caches Anthropic prefix
    Agent->>LLM: call_structured → RAIDLog
    LLM-->>Agent: RAIDLog
    Orch->>Session: session.raid = ...

    Orch->>Agent: Stakeholder / Status generators (wbs + raid context)
    Orch->>Session: save_artifacts, snapshot v1

    loop review / revision
        User->>Entry: feedback + target (wbs|raid|both|all|...)
        Entry->>Orch: apply_revision(session, target, feedback)
        Orch->>Agent: RevisionAgent.run(artifacts, feedback, target)
        Note over Agent: BOTH/ALL: WBS helper then RAID uses updated WBS
        Agent->>LLM: one or more structured revision calls
        LLM-->>Agent: RevisionResult
        Orch->>Session: merge result, revision_count++, versions/
    end
```

## Notes

- **No direct agent-to-agent messaging.** Each specialist agent is stateless; `OrchestratorAgent` owns `WorkplanSession` and passes Pydantic models as arguments.
- **LLM messages** are built per call via `BaseAgent.build_messages()` → `provider.call_structured()` (routed to OpenAI or Anthropic by model name).
- **Web flow** splits parse and build: `parse_brief_only` may stop at `AWAITING_CONFIRMATION` before `generate_workplan_artifacts`.
